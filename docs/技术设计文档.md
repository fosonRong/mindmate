## 1. 设计目标与约束

| 目标 | 约束 |
| --- | --- |
| 安装包非常小 | 桌面安装包 ≤ 10MB（目标 3–8MB），不打包运行时与浏览器内核 |
| 双架构 | 桌面端（C/S）与浏览器端（B/S）共享同一后端、同一数据、同一套 API，功能零分裂 |
| AI 原生 | 流式输出、结构化输出、可配置 DeepSeek / 智谱 GLM 等任意 OpenAI 兼容模型 |
| 本地优先 | 默认本地模式零依赖运行；服务器模式通过同一二进制无头部署 |
| 数据安全 | API Key 仅存系统安全存储；访问密码 Argon2；敏感内容可选脱敏 |

**核心决策**：**单一 Rust 二进制同时充当"桌面壳进程 + HTTP 后端 + 提醒调度器"**。桌面 WebView 与浏览器都是纯 HTTP 客户端，走完全相同的 REST/SSE 接口；Tauri 仅贡献窗口壳与系统能力（托盘/热键/通知/自启）。

### 2.2 统一前端接入模型（关键设计）

**桌面端与浏览器端共用同一套 HTTP API，前端产物只构建一份。**

| 形态 | 前端加载方式 | API 访问方式 |
| --- | --- | --- |
| 桌面端（本地模式） | 由 Rust 核心 axum `ServeDir` 托管前端静态产物，WebView 加载 `http://127.0.0.1:{port}/` | 同源 HTTP + SSE，无 CORS 问题 |
| 浏览器端（局域网/服务器） | 同一份静态产物，由后端托管 | 同源 HTTP + SSE |

- 前端代码 100% 复用；桌面端唯一的差异层由 Rust 侧通过 **自定义协议**（`mindmate://`）或注入的 API 接口暴露系统能力；
- 开发模式：Vite dev server 代理 `/api` 到后端，热更新；
- **不使用 Tauri IPC 作为业务通道**：业务一律走 HTTP，IPC 仅用于系统能力（通知点击回调、热键触发）。

### 2.3 三种运行模式（同一二进制）

| 模式 | 启动参数 | 表现 |
| --- | --- | --- |
| 本地（默认） | `--mode local` | 启动 Tauri 窗口 + 本机 HTTP（默认端口 17801，冲突自动 +1）；绑定 127.0.0.1；可选 `--lan` 开启局域网监听 + 访问密码 |
| 局域网 | `--mode lan` | 绑定 0.0.0.0，启用访问密码（首次启动引导设置） |
| 服务器 | `--mode server --headless` | 无窗口纯后端；Docker 容器中运行；绑定 0.0.0.0；HTTPS 由反向代理终止 |

## 3. 数据模型设计（SQLite）

### 3.1 连接与优化

- 单连接（后端唯一写入口）+ **WAL 模式**（读写并发）；
- `PRAGMA journal_mode=WAL; synchronous=NORMAL; foreign_keys=ON; busy_timeout=5000;`
- 所有写操作走 `rusqlite::Transaction`；数据目录：`{用户数据目录}/mindmate/data.db`（Windows `%APPDATA%` / macOS `~/Library/Application Support`，服务器模式 `--data-dir`）。
- Schema 版本：`PRAGMA user_version` + `migrations/` 目录顺序迁移（`migration_001.sql …`）。

### 3.2 DDL（核心表）

```sql
-- 记录节点：一次录入 = 一行
CREATE TABLE nodes (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  content     TEXT NOT NULL,                          -- 录入内容
  date        TEXT NOT NULL,                          -- 归属日 'YYYY-MM-DD'（本地时区）
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),-- 录入时刻，本地时区
  updated_at  TEXT NOT NULL DEFAULT (datetime('now')),
  is_backfill INTEGER NOT NULL DEFAULT 0,             -- 补录标记
  tags        TEXT NOT NULL DEFAULT '[]',             -- JSON 数组 ['工作']
  todo_id     INTEGER REFERENCES todos(id),           -- 关联待办（可选）
  deleted_at  TEXT                                  -- 软删除（同步留痕）
);
CREATE INDEX idx_nodes_date ON nodes(date, created_at DESC);

-- 待办
CREATE TABLE todos (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  title        TEXT NOT NULL,
  description  TEXT DEFAULT '',
  due_date     TEXT NOT NULL,                         -- 'YYYY-MM-DD'
  due_time     TEXT,                                  -- 'HH:MM'（日程类必填）
  remind_at    TEXT,                                  -- 提醒时刻（ISO，可空=不提醒）
  priority     TEXT NOT NULL DEFAULT '中',            -- 高/中/低
  tags         TEXT NOT NULL DEFAULT '[]',
  status       TEXT NOT NULL DEFAULT '待处理',        -- 待处理/进行中/已完成/已逾期
  repeat_rule  TEXT,                                  -- 'daily|weekly|monthly:…'（P2）
  category     TEXT NOT NULL DEFAULT '日程',          -- 今日/本周/本月/日程（按 due_date 自动归类，可手动改）
  sort_order   INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT,
  deleted_at   TEXT
);
CREATE INDEX idx_todos_due ON todos(due_date, status);
CREATE INDEX idx_todos_cat ON todos(category, status);

-- 设置（KV）：remind_freq / remind_window / daily_goal / ai_preset / ai_model / theme / deploy…
CREATE TABLE settings (
  key        TEXT PRIMARY KEY,
  value      TEXT NOT NULL,
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 报告归档
CREATE TABLE reports (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  type       TEXT NOT NULL,           -- daily/weekly/monthly/brief/goodnight/review
  period     TEXT NOT NULL,           -- '2026-09-12' | '2026-W37' | '2026-09'
  content    TEXT NOT NULL,           -- Markdown
  is_ai      INTEGER NOT NULL DEFAULT 1, -- 0=模板拼装降级
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE(type, period, created_at)
);
CREATE INDEX idx_reports_period ON reports(type, period);

-- Prompt 模板（可覆盖默认）
CREATE TABLE templates (
  type      TEXT PRIMARY KEY,         -- daily/weekly/monthly/brief/goodnight/review/qa
  content   TEXT NOT NULL,
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 智伴问答历史
CREATE TABLE chat_messages (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL DEFAULT 'default',
  role       TEXT NOT NULL,           -- user/assistant
  content    TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 成就（本地）
CREATE TABLE achievements (
  id         TEXT PRIMARY KEY,        -- 'streak_3' …
  unlocked_at TEXT NOT NULL
);

-- 用户（单用户默认；多用户 P2）
CREATE TABLE users (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  username     TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,        -- Argon2id
  role         TEXT NOT NULL DEFAULT 'owner'
);

-- 同步游标（多端增量拉取）
CREATE TABLE sync_state (
  kind  TEXT PRIMARY KEY,             -- 'nodes' | 'todos' | 'reports' | 'settings'
  last_id INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 3.3 统计查询（进度/趋势）

| 需求 | 查询 |
| --- | --- |
| 今日记录进度 | `SELECT COUNT(*) FROM nodes WHERE date=@today AND deleted_at IS NULL` |
| 连续记录天数 | 按 `date` 去重后计算最长连续段（Rust 侧实现，单次 `GROUP BY date`） |
| 待办完成率（周期） | `COUNT(*) / SUM(status='已完成')` 按 `due_date` 范围加 `category` 过滤 |
| 周/月聚合视图 | `SELECT date, COUNT(*) … GROUP BY date` 一次取整周期 |

## 4. API 设计

### 4.1 通用约定

- 前缀 `/api/v1`；响应统一包裹：`{ "code": 0, "data": …, "message": "ok" }`，`code != 0` 为错误（错误码表见 4.6）；
- 认证：`Authorization: Bearer <token>`（本地 token 或 JWT）；
- 所有写接口在事务内完成并**广播事件**（见 4.4）；
- 时区：请求与响应均用本地时区 ISO8601 字符串；日期字段一律 `YYYY-MM-DD`。

### 4.2 记录与周期

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/nodes` | 新建节点 `{content, date?, tags?, todo_id?}`；`date` 缺省=今天 |
| GET | `/api/v1/nodes?date=YYYY-MM-DD` | 当日节点（按 created_at 升序） |
| GET | `/api/v1/nodes/range?from&to` | 周期聚合（周/月视图一次拉取） |
| PATCH | `/api/v1/nodes/:id` | 编辑内容/tags/todo_id |
| DELETE | `/api/v1/nodes/:id` | 软删除 |
| GET | `/api/v1/stats/daily?date=` | 记录数/目标/达标/连续天数/待办完成率 |
| GET | `/api/v1/stats/period?from&to` | 周/月统计（每日节点数、完成率序列） |

### 4.3 待办

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/todos?category=&status=&priority=&tag=&q=` | 列表 + 筛选 + 搜索 |
| POST | `/api/v1/todos` | 新建；`category` 自动归类（服务端计算） |
| PATCH | `/api/v1/todos/:id` | 编辑/改期（改 due_date 时重算 category） |
| POST | `/api/v1/todos/:id/complete` | 勾选完成（记录 completed_at，广播事件） |
| POST | `/api/v1/todos/:id/reopen` | 撤销完成 |
| DELETE | `/api/v1/todos/:id` | 软删除 |
| GET | `/api/v1/todos/schedule?date=YYYY-MM-DD` | 某日【日程 + 待办】双栏数据 |

### 4.4 事件流（SSE）

- `GET /api/v1/stream/events?token=…`：`EventSource` 长连接；
- 实现：`tokio::sync::broadcast`（容量 1024，慢消费者丢弃并客户端重连全量拉取）；
- 事件类型（`event:` 字段）：

```
node.created / node.updated / node.deleted
todo.created / todo.updated / todo.deleted / todo.completed
report.saved · settings.updated · reminder.triggered
```

- 客户端收到事件后：更新 Pinia store 对应切片；若断线重连则按 `sync_state` 增量拉取。

### 4.5 AI 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/ai/presets` | 预设列表（GLM/DeepSeek/OpenAI/Qwen/Kimi/Ollama） |
| POST | `/api/v1/ai/config` | 保存配置（Key 经此进入系统安全存储，不回读） |
| POST | `/api/v1/ai/test` | 测试连接：最小请求 + 延迟回显 |
| POST | `/api/v1/ai/report` | 生成报告 `{type: daily|weekly|monthly, period}` → **SSE 流式响应** |
| POST | `/api/v1/ai/brief` | 晨间简报（同流式） |
| POST | `/api/v1/ai/goodnight` | 晚安总结（同上） |
| POST | `/api/v1/ai/review` | 周度复盘（同上） |
| POST | `/api/v1/ai/chat` | 智伴问答（流式；服务端先本地检索组装上下文） |
| POST | `/api/v1/ai/actions/replan` | 智能排期建议（单条待办） |

**AI 流式协议**：请求为普通 POST（`Accept: text/event-stream`），响应为 SSE 流：`data: {"delta": "…"}` 逐段；结束 `data: {"done": true, "usage": {…}}`；错误 `data: {"error": {"code": …, "message": …}}`。

### 4.6 认证与会话

| 模式 | 流程 |
| --- | --- |
| 本地 | 启动生成随机 32 字节 token → 写 `${dataDir}/.token`（600 权限）→ 桌面端启动时经 `mindmate://` 注入头部；浏览器本机访问时引导输入"/从桌面端复制 token"（或跳过，仅绑定回环地址） |
| 局域网/服务器 | `POST /api/v1/auth/login {password}` → argon2 校验 → 签发 JWT（有效期 30 天，`HS256`，密钥存数据目录随机生成） |
| 会话保护 | JWT 中带 `role`；所有写接口校验；口令错误 5 次锁定 10 分钟（内存计数） |

### 4.7 错误码

| code | 含义 |
| --- | --- |
| 0 | 成功 |
| 4001 | 参数校验失败 |
| 4002 | 未认证 |
| 4003 | 权限不足 |
| 4004 | 资源不存在 |
| 4005 | 冲突（并发写覆盖） |
| 4101 | AI：未配置模型 |
| 4102 | AI：网络/上游错误（附可读 message） |
| 4103 | AI：限流/超时 |
| 4201 | 密码错误 / 锁定 |
| 5000 | 服务内部错误 |

## 5. AI 接入层设计

### 5.1 统一客户端

- `async-openai` 配置自定义 `base_url`（每预设不同）+ `api_key`（从系统安全存储读取）；
- 模型配置结构：`AiConfig { provider, base_url, api_key_ref, model, temperature, max_tokens, reasoning_model? }`，存 `settings` 表 + Key 存安全存储；配置更新后广播 `settings.updated`，AI 服务热重载。

### 5.2 流式管线

```
业务请求 ─▶ 组装 messages(模板填充) ─▶ 脱敏 regex 过滤 ─▶ CreateChatCompletionRequest{stream:true}
   ▶ async_openai::ChatCompletionStream ▶ 逐 chunk 解出 delta
   ▶ 反向脱敏（占位符还原）▶ SSE 转发客户端
   ▶ 结束: 统计 usage → tracing 日志 + （P2）调用记录表
```

- 首 token 超时 60s；整体超时 300s；失败退避重试 3 次（1s/3s/9s，仅 429/5xx/连接错误）；
- 客户端中断：取消 future（`tokio::select!` + `CancellationToken`），上游 `abort`；
- 中文安全：请求体 `model: {temperature}` warm 参数按预设；`max_tokens` 默认 2048。

### 5.3 无 Key 降级（本地模板拼装）

未配置模型时 `POST /api/v1/ai/report` 返回 `is_ai: 0` 的本地拼装 Markdown（按模板纯字符串拼接：今日完成=各节点要点化、进度=统计值、明日计划=未完成待办列表），响应非流式；前端提示"配置 AI 获得更佳效果"。

### 5.4 智伴问答（本地检索 + LLM）

1. 解析用户问题（不调 LLM）：提取日期关键词（"周三/昨天/本周/本月"）与状态词；
2. 本地检索：FTS5 全文索引 nodes/todos（`CREATE VIRTUAL TABLE nodes_fts USING fts5(content, content='nodes')`，触发器同步）；
3. 组装上下文片段（上限 ~4K tokens）+ 问题 → `chat/completions` 流式回答；
4. 回答末尾附带"数据来源"引用列表（日期+摘要），保证可溯源。

### 5.5 Prompt 模板引擎

- `templates` 表 + 内置默认（启动时若缺省则写入）；
- 变量替换：`{{date}} {{nodes}} {{todos}} {{progress}} {{insights}} {{period}}`；
- 模板文本限制 8K 字符；渲染失败回退默认模板。

## 6. 提醒系统设计

### 6.1 调度器

| 场景 | 实现 |
| --- | --- |
| 记录提醒（间隔） | 启动时计算下次触发点：`now + interval` 对齐整点；`tokio::time::interval` 或单次 sleep + 重排；区间 `[window_start, window_end]` 内才触发 |
| Cron 提醒 | `cron::Schedule` 解析 + 计算 next() 单次 sleep |
| 待办提醒 | 内存最小堆（`BinaryHeap<(Instant, todo_id)>`）+ 启动扫描当日 remind_at |
| 睡眠唤醒补偿 | 每次 tick 检查 `now - last_tick > 2×interval` → 聚合为一条补偿提醒 |

### 6.2 上下文智能提醒（L1 规则，纯 Rust）

```
should_notify(now) → RulesOutcome:
  if 勿扰时段: SKIP
  elif 当日已录数 >= daily_goal: SKIP(静默)
  elif missed_days >= 2: KIND(关怀文案)
  elif 存在已逾期待办: URGENT(附加逾期标题, 最多 2 条)
  else: NORMAL(常规文案: 已录 n/目标 m)
```

- 规则全部有对应设置开关与说明（设置页），无 AI 参与，行为可预期。

### 6.3 投递链

```
调度器 → 生成 Notification{title, body, kind} → 投递器(多通道):
  ├─ 桌面通知: tauri-plugin-notification（点击 → 前端事件 reminder.quick_entry 打开速记浮窗）
  ├─ Web 长连接: 经 SSE broadcast 推 `reminder.triggered` → 浏览器页面内横幅/浏览器通知
  └─ (P1) 邮件/Webhook: 异步任务发送
```

- 配额：记录提醒 1 条/间隔内至多 1 条；待办提醒全局每分钟至多 5 条（防刷屏）；
- 勿扰优先级最高：一次性（如 14:00–15:00 会议）与重复（如每天 12:00–13:00）两种规则，存 `settings`。

| --- | --- | --- |
| 托盘常驻 | `tauri-plugin-tray` + `Menu` | 关闭窗口=隐藏到托盘；托盘菜单：打开/速记/暂停提醒/退出 |
| 全局热键 | `globalShortcut`（Rust API） | 默认 `Alt+Z`，注册失败回退提示；触发 → 显示速记浮窗窗口（always-on-top、无边框、置中偏上） |
| 系统通知 | `tauri-plugin-notification` | 见 6.3 |
| 开机自启 | 自研（`src-tauri/src/autostart.rs`） | Windows 写 `HKCU\...\Run`、macOS 写 LaunchAgent、Linux 写 autostart desktop 文件；命令 `autostart_status` / `autostart_set`，失败以「读回状态」判定并返回可读中文错误。设置页开关 |
| 单实例 | `tauri-plugin-single-instance` | 二次启动聚焦已有窗口 |
| 睡眠补偿 | Rust 侧 `check_tick_gap()`（无需系统事件，启动/定时即可） | 见 6.1 |
| 速记浮窗 | 第二个窗口（`label: "quick"`，`decorations:false, alwaysOnTop:true, skipTaskbar:true`） | 加载 `/#/quick` 路由；Enter 提交 → POST /nodes → **隐藏窗口**（`close_quick_entry`）；再次 Alt+Z 收起（切换语义，作为页面异常时的逃生口） |

> 桌面端通过 `mindmate://` 自定义协议向前端暴露 `companion` API（isDesktop / openQuickEntry / focusWindow / copyToClipboard），前端据此渲染桌面专属入口（热键提示、托盘联动），浏览器端同函数为空实现。

### 7.1 桌面端 IPC 授权（易踩坑，务必遵守）

桌面窗口加载的是**本机 HTTP 页面**（`http://127.0.0.1:<端口>`），在 Tauri 2 中这属于 **remote 来源**。remote 来源的 `invoke` 受 ACL 严格限制，必须同时满足两条，否则一律被拒（前端只看到 `Command xxx not allowed by ACL`）：

1. **放行来源**：`src-tauri/capabilities/default.json` 里声明
   `"remote": { "urls": ["http://127.0.0.1:*", "http://localhost:*"] }`
   —— 端口会因占用自增（17801 → 17820），**不能写死**。
2. **声明应用自身命令**：`src-tauri/build.rs` 必须用 app manifest 列出所有自定义命令，
   ```rust
   tauri_build::try_build(tauri_build::Attributes::new().app_manifest(
       tauri_build::AppManifest::new().commands(&["open_quick_entry", "close_quick_entry",
                                                  "backend_port", "autostart_status", "autostart_set"])))
   ```
   构建期为每条命令生成 `allow-<命令名连字符化>` / `deny-<...>` 权限，capability 以**不带插件前缀**的形式引用（如 `"allow-autostart-set"`）。
   缺少这一步时应用命令没有任何 ACL 条目，`invoke.acl` 为空 → 直接拒绝。

> 用 `try_build` 而非 `build`，权限写错在**构建期**即报错，不必等到运行期才发现"点了没反应"。
> 回归护栏：`scripts/desktop_test.py`（29 项）会校验上述两条与浮窗生命周期，已纳入 `run_all_tests.py`。

**浮窗生命周期铁律**：窗口只 `hide()`，**永不 `window.close()`**。Windows/WebView2 上 JS 侧 `window.close()` 会销毁网页视图，
只留下一个无内容、无按钮、Esc 无效的无边框置顶白窗，且此后任何脚本注入都会抛 `WebView2 error 0x8007139F`；
浮窗的 `CloseRequested` 事件也统一降级为隐藏（`api.prevent_close()`）。

## 8. 前端架构（apps/web）

### 8.1 目录

```
apps/web/src/
├── api/            # fetch 封装 + SSE client（EventSource 自动重连、断线增量拉取）
│   └── types.ts    # 与 Rust serde 对齐的 TS 类型（手写维护 + 契约测试）
├── stores/         # Pinia: nodes / todos / ai / settings / sync
├── views/          # Today / Week / Month / Todos / Companion / Settings / Quick
├── components/     # ProgressBar, NodeTimeline, TodoItem, Calendar, ReportViewer, ChatPanel…
├── router/         # vue-router: / (今日) /week /month /todos /companion /settings /quick
├── lib/            # markdown 渲染(marked+DOMPurify), 日期工具(dayjs 本地化), 脱敏预览
└── composables/    # useSSE, useStreaming(打字机), useReminder
```

### 8.2 状态与同步

- Pinia store 为单一事实源；写操作先调 API，成功后应用响应并**依赖 SSE 事件二次校正**（多端一致）；
- `useSSE` 单例：连接失败指数退避（1s/2s/4s…上限 30s），重连后按 `sync_state` 增量拉取缺失数据；
- 流式渲染：`useStreaming` 维护 `accumulated` + `displayed` 双缓冲（打字机节流 16ms/帧），支持"复制完整文本/中止生成"。

### 8.3 日历/周视图渲染

- 周/月视图数据一次 `range` 拉取后本地聚合，避免 N+1；网格虚拟滚动（月视图条目多时，`vue-virtual-scroller` 按需引入）。

## 9. 多端一致性与并发

| 问题 | 方案 |
| --- | --- |
| 双端同时编辑同一节点 | 已存 `updated_at`；写入方携带 `updated_at`，不匹配返回 4005；前端提示"已被另一端修改，已刷新"并重载该条 |
| 断线期间漏事件 | SSE 重连后按 `sync_state.last_id` 增量拉取（nodes/todos/reports） |
| 桌面与浏览器同时提醒 | 全局 `reminder` 事件在投递时按"已投递 id 去重"（内存 Set + 10 分钟过期） |
| 服务器模式多客户端 | 同一 broadcast channel，天然广播 |

## 10. 安全设计

| 项 | 方案 |
| --- | --- |
| API Key | keyring-rs 存系统安全存储（Win=Credential Manager / macOS=Keychain / Linux=Secret Service），Rust 进程内持引用；前端永不回读 |
| 本地 token | 随机 32B，写盘 0600；绑定 127.0.0.1；CORS 仅允许同源（同端口） |
| 访问密码 | Argon2id（m=64MB, t=3, p=1）；登录限速（见 4.6） |
| JWT | HS256，密钥首次启动生成存数据目录（0600），30 天过期 |
| 传输 | 服务器模式强制要求 TLS 反代（文档指引）；Docker 内默认 HTTP 仅监听内网 |
| 脱敏 | 正则替换词表（默认：手机号/身份证/邮箱/网址 → `[隐私]`），设置页可自定义词组；AI 请求前应用 |
| 注入防护 | 前后端均参数化 SQL（rusqlite 绑定）；SSE 仅接受带有效 token 的连接 |
| 前端 XSS | 报告 Markdown 经 DOMPurify 白名单清洗后渲染 |
