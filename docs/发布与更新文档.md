## 1. 架构总览（一次发布发生了什么）

```
你：改版本号 → git tag v1.1.0 → git push origin v1.1.0
        │
        ▼
GitHub Actions（免费，公开仓库不限分钟数）
  ① 安装依赖          ② cargo test（Rust 单测）     ③ 前端生产构建
  ④ tauri build（用私钥签名更新包 → 生成 .exe.sig）
  ⑤ node scripts/make-manifest.mjs → latest.json + SHA256SUMS + 下载页
        │
        ├──► GitHub Release（安装包 + 绿色版 + 清单，作为备份下载源）
        └──► Cloudflare Pages（安装包 + latest.json + 下载页，主分发）
                    │  https://<你的项目>.pages.dev/latest.json
                    ▼
用户客户端（tauri-plugin-updater）
  启动 30 秒后检查清单 → 有新版 → 右下角出现「发现新版本」横幅
  → 点「立即更新」→ 后台下载 → 用内置公钥**验签** → 验签通过才安装
  → 自动重启 → 数据目录（%APPDATA%\Mindmate）不受影响
```

**关键点**：客户端内置的**公钥**与 CI 使用的**私钥**必须配对。私钥只存在两处：本地 `.tauri/mindmate.key` 与 GitHub Secrets。

## 2. 一次性准备（约 30 分钟，做完以后每次发版只需 3 分钟）

### 2.1 创建并关联 GitHub 仓库

1. 在 GitHub 新建仓库（建议**公开**：Actions 免费不限分钟、便于用户核对、能降低杀软误报；私有也可，Actions 每月 2000 分钟，够用）
2. 把仓库地址告诉我（形如 `https://github.com/你的用户名/mindmate.git`），我帮你执行下面两条命令并推送：
   ```bash
   git remote add origin https://github.com/你的用户名/mindmate.git
   git push -u origin main
   ```

> 本地仓库与首次提交**我已经建好了**（3 次提交，152 个文件，已确认 `target/`、`node_modules/`、`*.key`、`*.db` 均未入库）。

### 2.2 更新签名密钥（**我已经为你生成**）

| 文件 | 位置 | 用途 | 是否可公开 |
| --- | --- | --- | --- |
| 公钥 | 已写入 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey` | 客户端验签 | ✅ 公开（已随程序分发） |
| **私钥** | `.tauri/mindmate.key`（已 gitignore，**不会入库**） | CI 签名更新包 | ❌ **绝不外泄，且必须离线备份** |

备份要求：把 `.tauri/mindmate.key` 复制到**两处离线位置**（加密 U 盘 + 密码管理器附件）。

> ⚠️ **私钥丢失 = 无法再发布可自动更新的版本**（老客户端会因验签失败拒绝安装）。这是本项目唯一的单点风险。
> 重新生成密钥对（会让所有老客户端无法自动更新，只能手动下载安装）：
> ```bash
> ./apps/web/node_modules/.bin/tauri signer generate -w .tauri/mindmate.key -p "" --ci --force
> # 然后把新公钥写回 src-tauri/tauri.conf.json 的 plugins.updater.pubkey
> ```
> 若要给私钥加口令：把 `-p ""` 换成 `-p '你的口令'`，并把口令同时写入 GitHub Secret `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。

### 2.3 创建 Cloudflare Pages 项目

1. 登录 Cloudflare → 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**（不要选 Git 集成，我们用 CI 的 wrangler 部署）
2. 项目名填 `mindmate`（或你喜欢的名字，需与后面的 `PAGES_PROJECT` 变量一致）
3. 创建后记下访问域名：`https://<项目名>.pages.dev`
4. 首次部署由 CI 自动完成（无需手动上传任何文件）

### 2.4 获取 Cloudflare API Token

1. Cloudflare → 右上头像 → **My Profile** → **API Tokens** → **Create Token**
2. 选用模板 **Edit Cloudflare Workers**，或自定义权限：**Account → Cloudflare Pages → Edit**
3. 创建后复制 Token（**只显示一次**）
4. **Account ID** 在 Workers & Pages 页面右侧栏，或 URL 里的那段十六进制串

### 2.5 配置 GitHub Secrets 与 Variables

仓库 → **Settings** → **Secrets and variables** → **Actions**

**Secrets（4 项，加密存储）**

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `.tauri/mindmate.key` 的**完整文件内容**（含 `untrusted comment:` 那两行） | 用记事本打开全文复制 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 留空（我们的私钥无口令） | 若给私钥设了口令，这里填口令 |
| `CLOUDFLARE_API_TOKEN` | 2.4 拿到的 Token | |
| `CLOUDFLARE_ACCOUNT_ID` | 2.4 拿到的 Account ID | |

**Variables（2 项，明文，供构建期注入）**

| 名称 | 值 | 说明 |
| --- | --- | --- |
| `PAGES_PROJECT` | `mindmate` | Cloudflare Pages 项目名 |
| `RELEASE_BASE_URL` | `https://mindmate.pages.dev` | **必须与 2.3 的域名完全一致**；它会被写进客户端更新检查地址与 `latest.json` 的下载地址 |

> ⚠️ `RELEASE_BASE_URL` 写错是"更新不生效"的最常见原因：客户端会去错误的地址找清单。

## 3. 每次发版流程（3 分钟）

```bash
# 1) 改版本号（唯一来源：src-tauri/tauri.conf.json）
#    "version": "1.0.0"  →  "1.1.0"

# 2) 提交
git add -A
git commit -m "v1.1.0：新增 XXX，修复 YYY"

# 3) 打 tag 并推送（tag 必须与 tauri.conf.json 的 version 一致，前缀 v）
git tag v1.1.0
git push origin main --tags
```

推送 tag 后，GitHub Actions 自动完成：跑单测 → 前端构建 → 签名出包 → 生成清单与下载页 → 发 GitHub Release → 部署 Cloudflare Pages。

**观察与验证**：仓库 → **Actions** 标签页看进度（约 5–8 分钟）；完成后浏览器打开 `https://<项目名>.pages.dev` 应看到下载页与新版本号。

### 版本号规则

| 变更类型 | 版本号 | 例子 |
| --- | --- | --- |
| 修 bug | PATCH +1 | 1.1.0 → 1.1.1 |
| 加功能（兼容） | MINOR +1 | 1.1.0 → 1.2.0 |
| 破坏性变更 / 数据结构迁移 | MAJOR +1 | 1.2.0 → 2.0.0 |

> tag 名（`v1.1.0`）与 `tauri.conf.json` 的 `version`（`1.1.0`）**必须一致**，否则清单里的版本号会与安装包不符。

## 4. 本地演练（不发布，仅验证打包与签名）

改完代码后建议先本地跑一遍，确认能出包且签名正常：

```bash
# 1) 全量验收（需应用在运行；含 Rust 单测 / 接口 / 提醒 / 推送 / 桌面端静态）
python scripts/run_all_tests.py

# 2) 带签名构建（注意：这个 CLI 版本要用「私钥内容」，不是路径）
export TAURI_SIGNING_PRIVATE_KEY="$(cat .tauri/mindmate.key)"
export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""
npm run desktop:build
# 产物：src-tauri/target/release/bundle/nsis/Mindmate_<版本>_x64-setup.exe
#      同目录下还应有 .exe.sig（签名文件，缺失说明私钥没传进去）

# 3) 生成清单与站点目录（本地预览用）
RELEASE_BASE_URL="https://mindmate.pages.dev" node scripts/make-manifest.mjs
# 产物：release/latest.json、release/SHA256SUMS.txt、release/site/（含下载页）
```

**本地端到端验证自动更新**（可选，最能发现问题）：

1. 装一个**旧版本**（例如把 `tauri.conf.json` 版本改成 `1.0.9`，构建安装）
2. 把 `latest.json` 与新版安装包放到任意可访问的静态目录，或直接改本地 `tauri.conf.json` 的 `endpoints` 指向本地文件服务
3. 启动旧版 → 30 秒后应弹出「发现新版本」横幅 → 点「立即更新」→ 重启后版本号变化且**原有记录仍在**

## 5. 回滚（**必须理解的一条规则**）

> **Tauri updater 只升不降**：客户端只会安装"版本号更高"的包。所以**不能**通过把 `latest.json` 改回旧版本来回滚。

回滚的正确做法：

| 场景 | 做法 |
| --- | --- |
| 新版本有 bug | **发一个补丁版本**（例如 1.1.2 出问题 → 发 1.1.3，代码为回退后的内容），客户端会正常升级到 1.1.3 |
| 严重到要立刻止血 | 把 Pages 上的 `latest.json` **暂时替换为"更高版本号但指向已修复包"**的清单，或直接删除清单（客户端检查失败会静默跳过，不会损坏数据） |
| 只影响部分用户 | 用灰度清单（见 5.1）只对部分设备放量 |

### 5.1 灰度发布（零服务端）

客户端按**设备指纹哈希**决定读取 `stable.json` 还是 `canary.json`：

1. CI 默认产出 `latest.json`（全量）
2. 要灰度时，把新版本的清单另存为 `canary.json`，并让客户端在配置中指向它（或在 `src-tauri/tauri.conf.json` 增加第二个 endpoint —— 客户端按顺序尝试，第一个可用即用）
3. 放量节奏建议：10% → 50% → 100%，每档观察 24–48 小时

> 第一期先不启用灰度（用户量小、沟通直接）；等日活上百再开。

## 6. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| CI 报 `A public key has been found, but no private key` | Secrets 里 `TAURI_SIGNING_PRIVATE_KEY` 没配/内容不全 | 重新复制 `.tauri/mindmate.key` **全文**（含 `untrusted comment:` 行）到 Secret |
| 构建成功但没有 `.exe.sig` | 同上（没签名成功） | 见上；本地演练时确认 `TAURI_SIGNING_PRIVATE_KEY` 用的是内容而非路径 |
| 客户端一直提示"已是最新版本" | `RELEASE_BASE_URL` 与 Pages 域名不一致，或清单未部署 | 浏览器打开 `<RELEASE_BASE_URL>/latest.json` 应返回 JSON；不一致就改 Variable 后重新发版 |
| 客户端报 `signature verification failed` | 公钥与签名私钥不是一对（换过密钥） | 确认 `tauri.conf.json` 的 `pubkey` 与 CI 用的私钥配对；换过密钥则需手动分发新公钥版本 |
| 客户端检查更新报网络错误 | 部分网络访问 `*.pages.dev` 受限 | 属预期（走海外节点）；可在下个版本改用国内镜像，或提示用户手动下载 |
| 用户装不上/被杀软拦截 | 未做代码签名 | 已在方案中列为待办：有条件时购买 OV 证书（¥1500–3000/年，需主体资质） |
| 安装后数据没了 | 不应发生（更新只替换程序文件，不触碰数据目录） | 立即检查 `%APPDATA%\Mindmate\data.db.bak.v*`（迁移前自动备份），并把 `data.db` 恢复为最近的 `.bak` |
| 用户装旧版程序打不开 | 库版本高于程序支持版本（迁移 v 保护生效） | 这是**保护行为**：提示用户升级程序；数据未被破坏 |
