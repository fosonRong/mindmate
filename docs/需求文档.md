## 1. 产品概述

### 1.1 背景与痛点

- **记不住**：埋头做事，到点写日报/周报时回忆困难，只能凭印象拼凑，内容失真；
- **管不住**：待办散落在脑海、便签、聊天记录中，无统一入口，容易遗漏和逾期；
- **养不成**：缺少外部提醒驱动，难以养成"定期记录"的习惯；
- **重复劳动**：写日报、周报、月报是重复劳动，耗时且格式不统一；
- **不会复盘**：数据记了一堆，却没人帮你看懂——哪类任务总拖延、什么时段效率高、习惯有没有变好。

### 1.2 产品定位与愿景

**智伴 Mindmate 不是备忘录，不是待办清单，也不是报表工具，而是一个智能伴侣。**

它提供一条完整闭环：**接住你的碎片记录 → 主动关心你的节奏 → 把碎片整理成价值 → 帮你复盘与改进**。

四个关键词：

| 关键词 | 含义 |
| --- | --- |
| 随时接住 | 桌面全局热键速记、浏览器随时打开、通知内直接记录，3 秒完成一次记录，零门槛 |
| 主动关心 | 提醒是"懂你"的：已达目标就安静，有逾期就提醒你，不会机械轰炸 |
| 整理成价值 | 晨间简报、日报/周报/月报、晚安总结，AI 一键生成 |
| 陪你成长 | 连续记录、周度智能复盘、习惯洞察，看见自己的进步 |

**三不原则**：不社交（无排名无分享）、不打扰（克制提醒，可全部关闭）、不上云（数据自持，AI 也只把内容发给你自己配置的模型）。

### 1.3 双架构形态（本版核心）

| 形态 | 载体 | 能力差异 | 适用场景 |
| --- | --- | --- | --- |
| **C/S 桌面端** | Tauri 2 桌面应用（Win/macOS，安装包约 3–8MB） | 全部能力：含系统级能力——托盘常驻、全局热键速记、原生系统通知、开机自启、睡眠唤醒补偿 | 主力使用：写代码/办公的工位场景 |
| **B/S 浏览器端** | 浏览器访问（Vue SPA，响应式） | 全部业务能力（记录/待办/报告/问答/提醒管理）；提醒降级为：页面内提醒 + 浏览器通知 + 可选邮件推送 | 随时随地：平板、手机浏览器、他人电脑、远程出差 |

**关键技术点**：两形态共享**同一后端服务**（本地运行或部署到服务器均可）、同一数据、同一 AI 能力；桌面端是浏览器端的"增强壳"（在 Web 能力之上叠加系统能力），不存在功能分裂。

### 1.4 目标用户与画像

**像 1**：小林，27 岁，研发工程师
> 每天写日报，项目多、杂事多、上下文切换频繁。需要低摩擦速记 + 到点提醒 + AI 日报，最看重"别打断我"。主力用桌面端热键。

**像 2**：阿 May，32 岁，产品经理
> 周报月报雷打不动，日程密集（会议、评审），待办跨周跨月。需要在公司和家、电脑和平板之间无缝切换，桌面记、路上看、浏览器摊开。

**像 3**：老徐，40 岁，团队负责人
> 经常出差，会议室只有浏览器；自我管理要求高，月度总结多，喜欢复盘数据。需要 B/S 随时随地访问 + 月报、周度复盘洞察。

### 1.5 核心用户场景（用户旅程）

| 场景 | 时长 | 智伴的介入 |
| --- | --- | --- |
| S1 晨间打开电脑 | 2 分钟 | 晨间简报：昨日未完成、今日日程与待办、AI 建议今日优先级（桌面端弹出 / 浏览器首页展示） |
| S2 上午工作中 | 3 秒/次 | 桌面全局热键唤出速记浮窗，录一句就关 |
| S3 每小时 / 出差途中 | 5 秒 | 上下文提醒（桌面通知 / 浏览器通知），未达标才提醒，点击直接速记 |
| S4 午休用手机 | 2 分钟 | 手机浏览器打开 B/S 页面，查看/补充上午记录与今日待办 |
| S5 下班前 | 1 分钟 | 生成今日日报草稿，确认后一键复制发出 |
| S6 周五下班 | 5 分钟 | 生成周报 + 周度智能复盘 |
| S7 月末出差中 | 10 分钟 | 酒店浏览器打开月报，查看本月待办达成与习惯趋势 |
| S8 睡前 | 2 分钟 | 晚安总结：今天完成了什么、未完成什么、明天建议 |

### 1.6 成功标准

| 指标 | 目标 |
| --- | --- |
| 留存行为 | 连续 7 天每日至少 1 条记录的用户占比 ≥ 40% |
| 低摩擦 | 单次记录操作耗时中位数 < 1 分钟；桌面热键/通知入口录入占比 ≥ 30% |
| 效率 | 日报生成 < 30 秒，周报/月报 < 1 分钟（不含用户确认时间） |
| 效果 | 待办逾期率月环比下降 ≥ 10% |
| 双端渗透 | 同时使用桌面端与浏览器端的活跃用户占比 ≥ 20%（说明跨端价值成立） |

## 2. 系统架构（本版核心）

### 2.1 总体架构：一套后端，两种前端

```
┌──────────────────────────────────────────────────────────────┐
│           智伴核心（单一 Rust 二进制）                           │
│  Tauri 2 + Rust 全栈：桌面壳 / B/S 后端 / 业务 / AI / 数据 合一    │
│  ├─ axum HTTP 服务：REST API + SSE 流式 + （可选）WebSocket      │
│  ├─ 记录/待办/报告/提醒 业务模块                                 │
│  ├─ AI 接入层（async-openai / reqwest SSE → OpenAI 兼容模型）    │
│  ├─ 数据层（rusqlite + FTS5 全文检索 + 迁移机制）                │
│  ├─ 认证（本地免登录 / 远程访问密码·JWT）                        │
│  └─ 密钥（系统安全存储：Credential Manager / Keychain）          │
└──────────────┬──────────────────────────────┬────────────────┘
               │ 前端产物 + IPC / HTTP        │ HTTP/SSE
     ┌─────────▼──────────┐        ┌──────────▼───────────┐
     │ C/S 桌面端           │        │ B/S 浏览器端           │
     │ 系统 WebView 加载前端 │        │ 同一后端，任意浏览器     │
     │ + 系统能力:           │        │ （局域网 / 远程服务器）  │
     │  托盘/热键/原生通知   │        └──────────────────────┘
     │  /开机自启/睡眠补偿   │
     └─────────────────────┘
```

**单一二进制的意义**：桌面端与本机后端是同一个进程；本地模式下该进程同时监听 `localhost` 端口供浏览器访问，服务器模式下同一份二进制以纯后端方式运行（无窗口）。因此**桌面端与浏览器端永远共享同一份数据与逻辑，不存在功能分裂**。

### 2.2 三种部署模式（由用户选择）

| 模式 | 说明 | 典型用法 |
| --- | --- | --- |
| **本地模式**（默认） | 后端随桌面端自动启动（localhost），浏览器可访问 `http://localhost:端口`；同一局域网内设备也可访问（可开关） | 个人主力使用；手机/平板在局域网内补充记录 |
| **局域网共享模式** | 同一后端监听局域网地址，家人/同事（经授权）通过浏览器访问 | 家庭内多设备、小团队内部使用 |
| **服务器模式** | 后端部署到云服务器 / NAS（提供 Docker 镜像），任何设备、任何地点通过浏览器访问；桌面端通过"连接服务器"配置接入 | 跨地域多设备、出差场景；数据自持在自己的服务器 |

**部署模式不影响任何业务功能**——同一套后端代码，仅启动参数与监听地址不同。

### 2.3 安全模型

| 模式 | 认证方式 | 传输 |
| --- | --- | --- |
| 本地模式 | 免登录（绑定 localhost + 随机启动 token），拒绝外部网络反射访问 | HTTP 仅限本机 |
| 局域网/服务器模式 | 访问密码（Argon2 哈希）或可选账号体系（JWT 会话）；登录后才能读写 | HTTPS（服务器模式建议反向代理 TLS；Docker 内置自签证书可选） |
| 密钥安全 | API Key 存**后端所在机器的系统安全存储**（本机=本机钥匙串；服务器=服务器安全存储），任何客户端（桌面/浏览器）都拿不到明文 | — |
| 多设备并发 | 单用户默认；多用户账号体系接口预留（P2） | — |

### 2.4 实时通信

| 通道 | 用途 |
| --- | --- |
| REST API（axum） | 常规 CRUD（记录/待办/报告/设置/认证） |
| 事件推送（SSE + 可选 WebSocket） | 提醒推送（记录提醒/待办提醒/勿扰状态）、多端操作实时同步（桌面录入 → 浏览器立即可见）、在线状态 |
| SSE 流式 | AI 报告/问答/简报 的逐字流式输出（打字机效果） |

### 2.5 技术栈全景

| 分层 | 选型 | 说明 |
| --- | --- | --- |
| 工程组织 | pnpm workspace Monorepo（`apps/desktop`「Rust+前端」 `apps/web`「纯浏览器 SPA」 `packages/*`） | 一套前端代码，两种产物（桌面内嵌 + 浏览器） |
| 后端 | **Rust + axum + tokio**（与桌面壳同一二进制） | 单二进制同时服务桌面与浏览器；无 Node 运行时 |
| Web 前端 | **Vue 3 + TypeScript + Vite + Pinia + Element Plus** | SPA 响应式，手机浏览器可用；桌面与浏览器共用 |
| 桌面壳 | **Tauri 2**（Rust） | 系统 WebView（Windows WebView2 / macOS WKWebView）嵌前端；托盘、全局热键、系统通知、开机自启、睡眠唤醒补偿；安装包约 3–8MB |
| AI 接入层 | **async-openai**（OpenAI 兼容客户端）或手写 reqwest + SSE | 通吃 DeepSeek/OpenAI/Qwen/Kimi/GLM/Ollama；流式接收 + 结构化 JSON 解析 |
| 检索/记忆 | SQLite **FTS5**（关键词全文检索） | 智伴问答"我周三记了什么"等本地检索，零额外部署 |
| 本地模型 | Ollama（作为提供商预设，外挂服务） | 需要完全离线时用 |
| 密钥存储 | keyring-rs（系统安全存储） | 见 2.3 |
| 认证 | 本地 token / 访问密码（argon2）/ JWT（可选多用户） | 见 2.3 |
| 打包分发 | Tauri 内置打包器（Win MSI/NSIS + macOS dmg，支持 7z 压缩）+ Dockerfile（服务器模式，配 `--headless` 纯后端） | 桌面安装包 + 一键部署镜像 |

**为什么用 Tauri 而不是 Electron**：Electron 打包自带整套 Chromium，安装包通常 100MB 级、内存常驻 300MB+；Tauri 使用系统 WebView（Windows WebView2 / macOS WKWebView），安装包约 3–8MB，且本项目的"后端/数据/AI/提醒定时器"全部随 Rust 二进制自带，**单一进程、单一二进制同时服务桌面与浏览器**，体积与内存需求均大幅下降。AI 逻辑用 Rust 实现（async-openai 流式）没有性能劣势；若未来要嵌入本地小模型，Rust + llama.cpp 反而是天然路径。**对"AI 原生 + 体积非常小 + 双架构"的组合，Tauri 是当前最优解。**

### 2.6 双端能力矩阵

| 能力 | 桌面端 C/S | 浏览器端 B/S |
| --- | --- | --- |
| 自由录入 / 时间线 / 日·周·月视图 | ✅ | ✅ |
| 待办 / 日程（左右分栏视图） | ✅ | ✅ |
| AI：晨间简报、日报、周报、月报、晚安总结、周度复盘、智伴问答 | ✅ | ✅ |
| 消息/报告流式输出、历史归档 | ✅ | ✅ |
| 记录提醒（上下文智能） | ✅ 系统通知 | ⚠️ 浏览器通知（需授权）+ 页面内提醒兜底 + 可选邮件推送（P2） |
| 待办提醒 | ✅ 系统通知 | ⚠️ 同上 |
| 托盘常驻 / 开机自启 / 睡眠唤醒补偿 | ✅ | ➖ 不适用（服务器模式由服务端定时器持续运行） |
| 全局热键速记浮窗 | ✅ | ➖ 不适用（浏览器端为页面内速记框，移动端浏览器也可录） |
| 离线可用 | 依赖后端可达性（本地模式=离线可用） | 依赖服务器可达性 |

**说明**：服务器模式下提醒由**服务端定时器**驱动（服务不关机提醒就有效），比桌面端"托盘常驻"更稳定；本地模式下由桌面端进程驱动。

## 3. 智伴智能闭环（核心概念）

### 3.1 智伴循环（Companion Loop）

```
        ┌─────────────────────────────────────────────┐
        │            智伴的一天（循环）                 │
   ┌────▼────┐      ┌──────────┐      ┌───────────┐  │
   │ 晨间简报 │───▶ │ 全天速记   │◀─── │ 上下文提醒  │  │
   │ 计划今日 │      │ 热键/通知 │     │ 驱动记录    │  │
   └────┬────┘      └──┬───────┘     └─────▲─────┘  │
        │              │                   │        │
        ▼              ▼                   │        │
   ┌──────────┐   ┌─────────┐         ┌────┴────┐   │
   │ 晚安总结  │◀──│ 日报生成 │         │ 周期归档 │   │
   │ 收束今日  │   │ 一键确认 │         │ 周/月报  │   │
   └────┬─────┘   └─────────┘         └────┬────┘   │
        │                                  │        │
        └────────────┬─────────────────────┘        │
                     ▼                              │
              ┌─────────────┐                       │
              │ 智能复盘洞察  │── 反哺明日计划 ────────┘
              │ 习惯/拖延/效率│
              └─────────────┘
```

### 3.2 智能能力分层

| 层级 | 能力 | 实现 | 离线可用 |
| --- | --- | --- | --- |
| L1 规则智能 | 上下文提醒（达标静默/逾期加压）、待办自动归类、逾期判定、进度计算、每日目标达成判断 | 服务端程序逻辑 | ✅ |
| L2 生成智能 | 晨间简报、日报/周报/月报、晚安总结、周度智能复盘 | 调用用户配置的大模型 | ❌（无 Key 时降级为模板拼装） |
| L3 对话智能 | 智伴问答：自然语言查询自己的数据（"我周三记了什么"） | 本地数据检索组装 + 大模型 | ❌ |

### 3.3 术语表

| 术语 | 说明 |
| --- | --- |
| 节点（Node） | **一次录入即一个节点**。用户自由录入一条内容，提交后自动生成，带录入时间戳 |
| 每日目标 | 用户设定的"每天希望录入多少条"（默认 4 条），驱动记录进度条，可关闭 |
| 连续记录（Streak） | 连续 N 天每日至少录入 1 条的记录，习惯养成的核心指标 |
| 待办 | 按归属周期自动归类：今日/本周/本月/日程 四类 |
| 待办日程 | 绑定具体日期（可精确到分钟）的待办，进入日程视图展示 |
| 晨间简报 | AI 生成的今日摘要：今日已录入内容（归纳润色）+ 昨日未完成 + 今日日程/待办 + AI 建议优先级；随用随生成，反映当下 |
| 晚安总结 | 每晚 AI 生成的今日收束：完成了什么、剩下什么、明日建议 |
| 周度智能复盘 | 每周 AI 生成的洞察报告：完成率、节奏、拖延规律、下周建议 |
| 报告 | 由 AI 按指定周期生成的结构化总结（日报/周报/月报），含已完成待办与当前进度 |
| 智伴问答 | 与 AI 对话，用自然语言查询、分析自己的本地数据 |
| 洞察（Insight） | 从用户数据中提取的规律性结论（如"周三待办逾期率最高"） |

```
│   └── 问答：智伴对话

    ├── [桌面] 托盘、速记浮窗（全局热键）、原生通知
```

## 5. 数据模型（SQLite，位于后端）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `nodes` | id, content, created_at(录入时刻), date(归属日), is_backfill, tags, todo_id(可关联待办) | 记录节点，一次录入一行 |
| `todos` | id, title, desc, due_date, due_time, remind_at, priority(高/中/低), tags, status(待处理/进行中/已完成/已逾期), repeat_rule, category | 待办，category 由 due_date 自动归类 |
| `settings` | key, value | 提醒频率、每日目标、AI 配置(Key 加密)、部署模式、推送渠道等 |
| `reports` | id, type(日/周/月), period(如 2026-09-12 / 2026-W37 / 2026-09), content(markdown), created_at | 报告归档，同周期重复生成覆盖并保留历史版本 |
| `chat_messages` | id, role, content, created_at | 智伴问答记录 |
| `templates` | type, prompt_template, updated_at | 各报告/简报的 Prompt 模板（内置默认，可覆盖） |
| `users` | id, username, password_hash(Argon2), role | 多用户账号（P2 预留，单用户时仅 1 条记录） |

**关键约束**：
- 节点按 `date + created_at` 索引；待办按 `due_date + status` 索引；
- 所有写入走事务（rusqlite 事务），异常退出不丢数据；
- API Key 不在数据库中明文存储：写入后端所在系统安全存储，数据库仅存引用。

## 7. AI 接入设计

### 7.1 架构

```
Rust 核心（axum / async-openai）             外部
───────────────────────────              ──────
报告/简报/问答/复盘 服务 ── 取 Key(系统安全存储) ──▶ OpenAI 兼容 API
   ◀── SSE 流式(chunk) ◀── 流式组装 ── stream:true
桌面端/浏览器  ──SSE 订阅──▶  打字机渲染
```

- **Key 只在核心**：存后端所在机器系统安全存储（本机=Credential Manager/Keychain；服务器=服务器安全存储），桌面与浏览器客户端均拿不到明文；
- **流式输出**：`POST {base}/chat/completions`，`stream: true`，Rust 核心逐段经 SSE 转发给客户端；
- **超时与重试**：单次请求 60s 超时，失败退避重试 3 次（1s/3s/9s），仍失败返回可读错误；
- **统一客户端**：全部走 OpenAI 兼容协议（async-openai 或手写 reqwest + SSE），DeepSeek 与智谱 GLM 均为兼容接口，AI 层无需厂家特判。

### 7.2 提供商预设（DeepSeek 与智谱 GLM 为默认双预设，其余可扩展）

| 预设 | Base URL | 推荐模型 | 说明 |
| --- | --- | --- | --- |
| **★ 智谱 GLM（默认推荐）** | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash`（免费）/ `glm-4-plus` | 免费模型零成本跑通全部 AI 功能；国内直连快；支持流式/JSON mode/工具调用 |
| **★ DeepSeek（推荐）** | `https://api.deepseek.com` | `deepseek-chat` / `deepseek-reasoner` | 性价比标杆，长报告质量好；支持流式/JSON mode/工具调用 |
| OpenAI | `https://api.openai.com/v1` | gpt-4o-mini | 国际/高质量需求 |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-plus | 阿里云 |
| Kimi | `https://api.moonshot.cn/v1` | moonshot-v1-8k | 长上下文 |
| Ollama（本地） | `http://localhost:11434/v1` | llama3.2 | 完全离线 |

> 进阶选项（P2）：智伴问答/周度复盘可选用 DeepSeek `deepseek-reasoner` 思考模型，提升分析深度；设置页提供"默认模型"与"推理模型"两个选择位，不配置推理模型时自动回落默认模型。

### 7.3 默认 Prompt 模板（节选，全部可编辑，变量 `{{date}}` `{{nodes}}` `{{todos}}` `{{progress}}` `{{insights}}` `{{period}}`）

**日报**：

```

{{nodes}}

{{todos}}
# 今日进度：{{progress}}

遇到的问题(无则省略) / 明日计划(无则说明)；要点化，禁止编造未记录的内容。
```

（晨间简报 / 晚安总结 / 周度复盘 / 智伴问答模板按 FR-5 各节实现，均为同一套变量机制。）

### 7.4 隐私与成本控制

- 仅发送所选周期的文本内容，附脱敏规则过滤（FR-5.16）；
- `max_tokens` 默认 2048 可配，防止超额；报告类 Prompt 明确"简洁"约束；
- 所有 AI 调用均需用户显式触发（生成按钮 / 自动生成开关可关闭），无后台偷偷调用；
- 调用日志（耗时 / token 数）本地记录与展示（P2）。

## 8. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 数据隐私 | 全部数据存后端 SQLite（本地模式=本机，服务器模式=自有服务器）；除用户主动触发且已配置模型的 AI 调用外零外部请求；Key 存后端系统安全存储 |
| 可用性 | 本地模式随桌面端自启自停；服务器模式 Docker 部署、服务级守护（systemd/PM2）；任一模式关闭窗口/页面不影响提醒（定时器在后端） |

| 易用性 | 首次启动引导：部署模式选择 → 每日目标 → 提醒频率 → AI 模型（可跳过）；双端同一套 UI 心智 |

## 10. 风险与开放问题

| 风险/问题 | 应对 |
| --- | --- |
| 用户关闭桌面应用提醒失效 | 本地模式=托盘常驻+开机自启；服务器模式=服务端定时器不受客户端影响 |
| 浏览器通知被拦截 | 首次引导请求通知权限；页面内横幅兜底；邮件/Webhook 推送（服务器模式） |
| 服务器模式的安全风险（公网暴露） | 访问密码（Argon2）+ 建议 HTTPS 反代 + 可选 VPN/内网穿透；默认建议本机/局域网 |
| AI 成本与隐私 | 默认提示可选本地 Ollama；仅发送所选周期文本；脱敏规则；调用日志透明 |
| 睡眠/休眠定时器漂移 | 唤醒后补偿触发（FR-4.8） |
| 自由录入内容零散 | 报告由 AI 归纳整理；晨间简报引导 |
| 全局热键冲突 | 默认 Alt+Z 可改，注册失败给提示并提供替代键 |
| 多端数据冲突（同改一条） | 乐观锁 + WS 广播，冲突以后写覆盖并提示 |
| 浏览器端无托盘/热键能力落差 | 明示能力矩阵（2.6）；提醒可靠性由服务端定时器兜底 |

**开放问题（需在开发中确认）**：
1. 局域网/服务器模式访问密码 vs 账号体系？（默认：单用户访问密码 + 预留多用户表）
2. 服务器模式是否需要多用户？（P2，先单用户）
3. 邮件/Webhook 推送优先级？（默认 P1，随 M6）

## 11. 验收标准（关键流程）

| 流程 | 验收标准（Given/When/Then） |
| --- | --- |
| 双端一致性 | 桌面端录入 1 条 → 浏览器端（同一后端）1 秒内时间线出现该节点 |
| 速记闭环（桌面） | 任意应用按 Alt+Z → 浮窗出现 → 回车 → 浮窗关闭且时间线新增 1 节点，时刻正确 |
| 一次录入一节点 | 连录 4 条 → 今日 4 个节点，进度 4/目标，无任何模板干预 |
| 上下文静默 | 今日达标 → 整点不弹通知；删 1 条 → 下次整点恢复 |
| 逾期提醒 | 待办超时未完成 → 状态「已逾期」+ 通知一次（桌面系统通知 / 浏览器通知） |
| 日报生成 | 点击生成 → SSE 流式出文 → 内容含全部节点要点与待办完成情况 → 复制 Markdown 正确 |
| 无 Key 降级 | 未配置模型生成日报 → 输出模板拼装文本 + "配置 AI 获得更佳效果"提示 |
| 睡眠唤醒 | 挂起 3 小时 → 唤醒后收到 1 条聚合补偿提醒 |
| 服务器模式 | Docker 部署到远端 → 浏览器跨地域登录访问 → 待办/记录/AI 报告全部可用；未授权访问被拒绝 |
| 数据安全 | 导出备份 → 清空导入 → 节点/待办/设置全部还原 |
