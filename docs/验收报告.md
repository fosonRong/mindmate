| 1 | 默认设置全部未写入数据库 | `settings.updated_at NOT NULL` 而种子插入未提供该字段，SQLite `OR IGNORE` 静默跳过 | 种子插入补齐 `updated_at` |

| 8 | `npm run test:rust` 在 npm 子进程中报「cargo 不是命令」 | npm 子进程不继承手工添加的 PATH（cargo 为用户级安装） | 新增 `scripts/run-cargo.mjs` 跨平台包装器，自动补齐 `~/.cargo/bin` |

| 10 | AI 生成的日报在历史里查不到（归档类型错乱） | 流式路径用 tag 推导归档 `(type, period)`，日报 tag 是日期 → 存成 `type="2026-09-12"` | 引入 `StreamPlan` 显式声明落库目标，落库统一到 `ai_stream_from` |
| 11 | 智伴问答的 AI 回复不落库（刷新即丢） | 助手消息只在降级分支写入 `chat_messages`，AI 分支遗漏 | 同上，统一在流式结束时落库 |
| 12 | 提醒生效时段/勿扰规则**跨零点失效**（如 22:00–02:00 永不触发） | 时段判定用 `now >= start && now <= end`，跨零点时 end < start | 新增 `in_window`（`start > end` 视为跨午夜）与 `in_dnd_rules` 纯函数 + 5 项单测 |

## 五之三、第二轮用户反馈修复记录（3 项，均已实测验证）

> 本轮三个问题同源：桌面窗口加载的是**本机 HTTP 页面**（`http://127.0.0.1:<端口>`），在 Tauri 2 中属于 **remote 来源**。
> 项目既未在 capability 的 `remote.urls` 放行该来源，也未在 `build.rs` 声明应用自身命令的 app manifest，
> 于是**前端所有 `invoke` 都被 ACL 拒绝**（`Command xxx not allowed by ACL`）——
> 这是「开机自启报错」与「速记浮窗白屏、Esc 关不掉」共同的根因。

| # | 反馈 | 根因 | 修复 | 验证证据 |
| --- | --- | --- | --- | --- |
| 1 | 设置开机自启仍然报错（上一轮未修复） | 桌面端 `invoke('autostart_set')` 被 ACL 拒绝：capability 缺 `remote.urls`；应用自身命令也未在 `build.rs` 的 app manifest 中声明 → `invoke.acl` 为空即拒绝 | ① capability 增加 `"remote": {"urls": ["http://127.0.0.1:*", "http://localhost:*"]}`（端口会因占用而自增，不能写死）；② `build.rs` 改用 `try_build` + `AppManifest::new().commands([...])` 声明 5 个命令，capability 引用自动生成的 `allow-*` 权限；③ `open_quick_entry` 返回布尔值，前端据此跳过浏览器兜底 | 实测（已重装到 `%LOCALAPPDATA%\Mindmate`）：点击开关 → toast「已开启开机自启（登录后自动启动智伴，提醒持续生效）」，注册表 `HKCU\...\Run` 出现 `Mindmate = "...\mindmate.exe"`；再点 → 键值被移除、提示已关闭。**修复前同一操作**：toast「设置开机自启失败：Command autostart_set not allowed by ACL」 |
| 2 | Alt+Z 速记浮窗按 Esc 关不掉、白屏 | `Quick.vue` 的 `closeWindow()` 调用了 `window.close()`——因为 `close_quick_entry` 同样被 ACL 拒绝，代码走了浏览器兜底。Windows/WebView2 上 `window.close()` 会**销毁网页视图**，只剩一个无内容、无按钮、Esc 无效的无边框置顶白窗；此后每次 Alt+Z 又会在已损坏的视图上注入脚本，触发 `WebView2 error 0x8007139F` | ① 彻底删除 `window.close()`，收起只走 `close_quick_entry`（隐藏窗口，WebView 保活）；② 浮窗 `CloseRequested` 一律降级为隐藏（`api.prevent_close()`），窗口永不销毁；③ 去掉未就绪即失败的 `eval` 注入，改由页面自身监听 `focus` / `visibilitychange` 复位并聚焦；④ Alt+Z 与托盘「速记」改为**切换**（可见即收起）——页面异常时的兜底逃生口 | 复现：旧构建下 Alt+Z → 写入内容回车 → 出现无法关闭的白窗、Esc 无反应，再次 Alt+Z 日志报 `0x8007139F`（本机复现，与用户反馈一致）。修复后同流程：浮窗正常渲染「⏺ 速记 / 今日 n/4」→ 保存后自动收起 → 再按 Alt+Z 内容仍正常渲染（旧代码此处已是白屏）→ 再按 Alt+Z 收起 → 点浮窗内「关闭」窗口隐藏；**日志 0 条 WebView2 错误**（修复前 6 条） |
| 3 | 今日记录节点文字上方空白过多，不美观 | 标签行 `.tl-meta` 即使没有标签也照常渲染，撑出 20px 空行，叠加 8px 段间距，正文上方共 43px 留白 | 标签行改为条件渲染 `v-if="node.tags.length || node.isBackfill"`；悬停「编辑/删除」移出文档流（绝对定位于气泡右上），不再参与布局 | 浏览器实测（同一构建，`getBoundingClientRect` 量取）：无标签节点 正文上方间距 **43px → 11px**、气泡高度 76px → 44px；含标签节点标签行仍正常渲染（20px 行高、两枚标签 chip 正常） |
