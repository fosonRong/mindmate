# 智伴 Mindmate · 「零散事项数字化与智能效率」迭代需求说明

> 版本：规划稿 v1（2026-09）
> 主线目标：帮用户把零散事项数字化、智能化，借助 AI 提高工作效率、让工作有迹可循、工作事项智能排期。
> 产品原则不变：**本地优先**（原始数据全在本机）、**AI 克制**（AI 给建议、用户拍板，入库前必经确认）、**离线兜底**（每个 AI 能力都有本地规则降级）。

---

## 一、背景与痛点（对齐五个目标关键词）

| 目标 | 现状 | 差距（痛点） |
| --- | --- | --- |
| 零散事项数字化 | 速记（文本一行=一节点）、收集箱、Ctrl+K/Alt+Z 入口 | 捕捉形态单一：开会口头交办、聊天里的事、截图里的文字、文件链接，都要手动转写；摩擦大 → 很多事根本没被记下来 |
| 智能化 | 智能速记拆待办、AI 打标、收集箱 | 记完没人管：收集箱堆着不归类；相关的事各记各的，互相不知道；会议/沟通记录要自己翻着提炼行动项 |
| AI 提高工作效率 | 简报/日报/周报/复盘/问答/周计划 | AI 集中在「总结报告」环节，日常每一步（该先做啥、这事有下文吗、和之前那事什么关系）没有 AI 参与 |
| 工作有迹可循 | 时间线 + 统一搜索 + 热力图 | 事是散的：某待办为什么做、依据哪条记录、写进了哪份报告，要靠人脑串；复盘/汇报时说不清「上周为 A 项目做了什么」 |
| 智能排期 | 拖拽排期、AI 排期建议（单条）、循环待办 | 排期整体靠脑：未排期池自己拖、容量自己估、逾期自己想起来顺延；缺「一键把一堆事排进一周」的引擎 |

---

## 二、迭代主线：三个版本（v1.4.0 → v1.4.1 → v1.5.0）

### v1.4.0 「随手捕捉」——零散事项数字化（预计 1 周）

| # | 需求 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 万能捕捉浮窗升级 | 现有 Alt+Z 桌面速记浮窗升级为常驻万能入口：一行文字回车后**智能分流**（含日期时间→待办草稿；普通→记录；迟疑→收集箱），浮窗内直接看到分流结果并可改 | 浮窗内完成「记→分→存」三步不切换窗口；分流结果与今日页智能速记一致（同一后端） |
| 2 | 剪贴板捕捉 | 复制任意文本（微信消息、邮件段落）后，浮窗显示「📋 粘贴成记录」，一键入库并自动附「来自剪贴板」来源标记 | 粘贴内容完整入库、可搜索；来源标记在详情可见 |
| 3 | 截图/图片速记（OCR） | 浮窗或速记区粘贴/拖入图片 → **本机 OCR**（Windows.Media.Ocr，系统自带、免费离线、中文支持好）→ 识别文本进入内容编辑，原图存本地并保留路径 | OCR 全程本机完成、断网可用；识别文本可编辑后入库；原图可从记录详情打开 |
| 4 | 链接/文件捕捉 | 拖入文件或粘贴链接 → 存为记录（链接附 URL，文件存本地路径），纳入统一搜索 | 记录含可点开的链接/文件路径；搜索命中 |
| 5 | 语音速记验证（P2） | 技术验证任务：Windows Web Speech / 本地 whisper 模型在 WebView2 的可用性、包体积、延迟 | 产出验证结论与 demo；可用则纳入 v1.5.0，不可用维持后备池 |

**边界**：不做聊天工具（微信/钉钉）自动抓取——合规与生态限制，保留手动复制粘贴路径。

### v1.4.1 「智能整理」——记了就有用（预计 1~1.5 周）

| # | 需求 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 收集箱 AI 自动分类 | 收集箱条目自动给出建议归类：**待办**（有动作语义/日期）/ **纯记录**（想法见闻）/ **参考资料**（链接、摘录），置信度高的一键采纳、逐条可改 | 建议可整体关闭（设置）；采纳/修改后入库路径与现有待办/记录一致 |
| 2 | 相关事项自动串联 | 同主题的记录与待办互相关联：本地规则优先（共用标签 + 关键词重合 + 时间邻近），用户配置 AI 后可选语义相似度增强；详情页显示「相关事项」区 | 串联全部本地可算（断网可用）；详情页一键跳转相关条目 |
| 3 | 提炼行动项 | 时间线里勾选多条记录（会议记录、聊天摘录）→ 一键「提炼行动项」：AI 抽取待办清单（复用拆待办弹窗逐条确认），入库打「行动项」标签并回链原记录 | 未配 AI 时按规则抽取（「XX 负责/周五前/下一步」句式）；确认后入库；行动项与来源记录互相可跳转 |
| 4 | 智能速记升级 | 支持一段话拆多个待办（已有）+ 新增：识别「等 X 回复 / 跟进 Y」→ 建议创建**跟进类待办**（带 N 天后提醒） | 跟进类待办打「跟进」标签、默认 3 天后提醒；可在确认弹窗改 |
| 5 | 相似内容提示 | 录入时本地检索相似历史记录（标题重合度），提示「已有相似记录」可跳转查看，避免重复记录 | 提示不打断输入（输入框下方轻提示）；点击跳转 |

### v1.5.0 「智能排期与有迹可循」——让工作自己排、事后说得清（预计 1.5~2 周）

| # | 需求 | 说明 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 一键智能排期引擎 | 收集箱 + 未排期待办，按 **优先级 × 截止日期 × 每日容量**（现有每日目标/工作日历/休息日规则）自动铺进未来一周；超载/冲突显式标注；结果先预览、一键应用、可整体撤销 | 排期不直接写库直到用户点「应用」；高优先+早截止先排；容量超限的日子明确提示；撤销完整还原 |
| 2 | 逾期智能顺延 | 逾期待办一键「顺延」：结合休息日与循环规则建议最近工作日，支持批量（本条+同类）；顺延记录进事项档案 | 顺延尊重法定休假表（与循环待办同源）；批量操作有确认 |
| 3 | 事项档案（可迹可循核心） | 任一待办/主题打开「档案」视图：**起因记录 → 相关事项 → 完成证据（哪条记录印证完成）→ 出现过的报告 → 完整时间线**，一条链路看完来龙去脉 | 档案数据全部来自本地检索（记录/待办/报告/标签关联）；每一步可点击跳转原文 |
| 4 | 周报证据引用 | 周报生成增强：按待办聚合本周记录，输出「关键事项与证据」段落（做了什么 + 对应记录摘要），汇报可直接引用 | 证据段落中的记录可点击回跳；AI 未配置时本地模板同样输出该段 |
| 5 | 跟进与等待视图 | 「等待他人」（waiting on）类待办独立视图：谁、什么事、等了几天；完成后可设「N 天后回看效果」的跟进提醒 | 等待视图从待办标签/状态筛出；回看提醒走现有提醒通道并支持推送 |

### 随版本带出的技术预研

- **对话式操作（AI Function Calling）**：预研「帮我把明天的会改到周四」式自然语言操作。智谱 GLM / OpenAI 兼容接口均已支持工具调用；需设计工具协议（查/改/建三类）+ 每步确认弹窗。结论进入 v1.6 排期评估。

---

## 三、本期明确不做

- 移动端 PWA、免费/Pro 商业化分级（v1.3.0 维持「仅记录，暂不实现」）
- 云同步、多人协作
- 微信/钉钉聊天记录自动抓取（合规与生态限制；保留手动复制粘贴路径）
- 全量向量化本地模型（体积与性能收益比不佳；语义增强仅在用户已配 AI 时按需调用）

## 四、技术依赖与风险

| 项 | 方案 | 风险与兜底 |
| --- | --- | --- |
| OCR | Windows.Media.Ocr（系统自带、离线、中文良好） | WebView2 暴露可用性需验证；不可用则降级「图片存档 + 手动粘贴文字」 |
| 语义相似度 | 本地规则（标签 + 关键词重合 + 邻近度）优先 | 规则召回不足时仅影响「相关」展示质量，不影响核心流；AI 增强为可选 |
| 排期引擎 | 纯本地规则（优先级/截止/容量/假期表），与循环待办假期表同源 | 引擎只产建议、用户确认后写库，避免「AI 乱改日程」信任问题 |
| Function Calling | 用户已配 AI 时可用 | 每个工具调用必须经确认弹窗；未配 AI 自动隐藏入口 |

## 五、发布节奏与流程

- v1.4.0 随手捕捉 → v1.4.1 智能整理 → v1.5.0 智能排期与档案；每版 1~2 周
- 流程照旧：**实现 → 全量验收 → 本地安装确认 → 用户确认后发布**（tag 取最高版本号）
- 各版验收标准落地时同步写入 docs/验收报告.md，守卫与 e2e 随代码交付
