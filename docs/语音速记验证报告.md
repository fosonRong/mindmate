# 语音速记技术验证报告（v1.4.0 · P2 验证任务）

> 结论先行：**采用 Web Speech API 特性探测方案**——运行环境可用就显示 🎤 按钮，不可用自动隐藏，不阻塞任何主流程。已随 v1.4.0 发布（灰度形态：可见即可用）。

## 1. 验证目标

评估在智伴的两种运行形态下做「语音 → 文字」的可行路径与成本：

| 形态 | 引擎 | 可用性 |
| --- | --- | --- |
| 桌面端（WebView2 / Edge 内核） | Web Speech API（`webkitSpeechRecognition`） | 依赖 Edge 在线语音服务；部分环境（离线/策略限制）不可用 → **特性探测 + 优雅降级** |
| 浏览器端（Chrome/Edge） | Web Speech API | Chrome/Edge 可用（走 Google/Edge 云服务）；Firefox/Safari 不支持 `SpeechRecognition` → 探测自动隐藏 |
| 桌面端本地模型（whisper.cpp / sherpa-onnx） | 离线 | 模型体积 40MB~1.5GB、集成成本高 → **暂缓**，等用户呼声再评估 |

## 2. 已实现（v1.4.0）

- `QuickEntry` 挂载时探测 `SpeechRecognition`：可用则显示「🎤 说」按钮
- 点击开始听写（zh-CN），结果追加进速记输入框 → 后续走现有链路（打标 / 拆待办 / 保存记录）
- 不可用环境（离线桌面、Firefox）按钮不出现，零成本零打扰

## 3. 已知限制与后续

1. WebView2 的在线语音服务在**企业策略/离线**环境可能被禁 → 按钮会出现但 `start()` 失败，已捕获并提示「语音识别启动失败」
2. 只做听写转文字，不做实时断句标点（引擎行为随平台）
3. 若后续用户反馈强需求离线语音，再评估 sherpa-onnx（中文流式识别，模型 ~40MB）作为可选下载组件
